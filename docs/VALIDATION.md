# 小规模验证方案（2 周，20–50 人）

## 要回答的问题

1. **选题这一步有没有用？** 用户愿意从选题开始，而不是直接写文案吗？
2. **文案能不能直接用？** 生成后多少人会保存草稿？
3. **简易生成够不够？** 有多少人生成后还要进制作台？
4. **愿不愿意排期？** 有没有人把选题排进未来的日子？
5. **花多少钱？** 每个活跃用户每周花多少点，换算成真实成本是多少。

## 看哪些数（后台 → 概览）

| 指标 | 来源 | 参考及格线 |
|---|---|---|
| 访问 → 出选题 | 漏斗 | ≥ 50% |
| 写文案 → 存草稿 | 漏斗 | ≥ 60% |
| 存草稿 → 提交生成 | 漏斗 | ≥ 40% |
| 生成成功率 | 概览卡片“失败 x%” | ≥ 90% |
| 排进排期 | 漏斗 | ≥ 20% |
| 第二周还回来的人 | 用户列表“最近活跃” | ≥ 30% |

及格线是起步参考，跑完第一周按实际情况调。

## 节奏

- **第 0 天**：自己和 2–3 个同事先完整跑一遍，修明显问题。
- **第 1 天**：发 10 个邀请码给最熟的种子用户，拉一个群收反馈。
- **第 3 天**：看漏斗哪一步掉得最多，约 3 个人做 15 分钟视频访谈。
- **第 7 天**：再发 20–40 个邀请码；按第一周花费调整 `DAILY_BUDGET_POINTS`。
- **第 14 天**：汇总漏斗、反馈原话、成本，决定下一步。

## 记录了哪些事件

- 服务端：`session` `register` `login` `topics_generated` `topic_created` `copy_generated` `draft_saved` `gen_started` `gen_done` `gen_failed` `final_started` `slot_set` `slot_approved` `asset_uploaded` `feedback`
- 前端：`page_view`（只记页面名）、`download`

只记动作和少量参数（模型、时长、花费），不记文案和素材内容。
